# 中华霸权天朝流官：调任、等级与法理约束设计

状态：v1.1.1 实施合同，2026-10-23。用户已授权开发、安装验证和推送 main；实现与验证结果另见本版开发记录。

已确认接口差异：用户接受原生授任结算后自动交旧、复核及纠正。第6、7节关于原生名单硬排除和授任前原子交旧的要求，在本版按此差异交付；兼容层自身挑选继任者仍须硬校验。不得宣称原生名单已被完全过滤，或宣称存在已验证的授任前钩子。

## 1. 适用范围

必须同时满足：存在中华霸权及其合法皇帝，角色实际处于该霸权统治体系下，并且属于流官制度，所处理事项属于该体系内的官职与领地。以实际头衔标识、制度／官职／契约及领主链判定，不以中文名称、文化、单一“天朝制”政府标签或角色最高等级判定。

其他地区自行改为天朝制的人物不适用。乱世中的割据帝国若没有中华霸权，整套限制不启用；不能因为其头衔是帝国级就追溯套用。中华霸权下的非流官制度角色同样不适用。中华霸权皇帝是回收终点，不按流官封臣的持有上限处理；帝国级尚书、同平章事、枢密使等朝官仍是封臣，不享有皇帝豁免。接任朝官后赴中华皇帝首都任职、世族领地迁至首都，复用现已实现的上游流程，不新增重复迁移或另行指定目的地。宗藩、世袭等其他身份不因同处中华霸权被自动当成流官。

每次执行前重验适用范围。角色或头衔因合法政治变动离开范围时，取消不再适用的旧任务；不能借修复之名从外国强行夺回合法战争所得。非法跨国授任的纠正，须有授任前的可信国家来源。

## 2. 最终持有规则：不再是“每个等级各一个”

| 流官最高官职 | 允许本人持有的领地头衔 | 必须交出 |
|---|---|---|
| 帝国级，如尚书 | 一份最高帝国级官职；另保留受保护世族身份 | 其余同级官职、所有王国／公国／伯爵及更低级领地头衔，以及全部领地封臣 |
| 王国级 | 一份最高王国级官职、最多一份本王国法理公国（优先王国首都所在公国），以及契约允许的本王国法理伯爵领 | 其余同级官职、超出一份名额的法理公国、所有外地公国、越界或超契约伯爵领 |
| 公爵级 | 一份最高公国级官职，以及契约允许、位于该公国法理内的伯爵领 | 其余同级官职、越界或超契约伯爵领 |
| 伯爵级 | 一份最高伯爵官职及其依法附属的男爵领 | 其余同级伯爵官职、越界领地 |

公爵／王国级人物的县领数量继续由原 Mod 的流官、防御使等契约决定；“多个合法县领可以保留”不等于可以保留外地县领。县领的原生附属男爵领沿上游规则，不另造通用男爵数量限制。帝国级流官明确不得保留任何低级领地头衔。

世族／家族身份头衔保留，不误当成普通土地清走。对一个已确认适用的流官，同级调任时“交出所有旧领地”的要求优先于旧设计按任命法筛选后只清一部分旧官职的做法；但不擅改第三方租赁权、其他角色财产或真实世族身份。

## 3. 法理约束同时检查本人领地与直接封臣

中华霸权下的地域法理层级是：中华皇帝（霸权）→ 王国级省份（如河南转运使）→ 公爵级镇（如某镇转运使／防御使）→ 伯爵级州县（如刺史／知州）。帝国级尚书官职不插入这条地域链，不授予任何省／镇／州县的法理统辖权。

地域官员以最终保留的王国／公国／伯爵官职为锚点，沿游戏当前实际法理链判定，不靠官名、地名、距离、地图颜色或首府猜测。

- 王国级流官：本人县领、直接封臣的主领地必须在该王国的法理后代范围内；可以统辖法理内的公爵，并可本人保留最多一个本王国法理公国，优先王国首都所在公国；其他法理公国应分封。首都所在公国须由王国实际首都县及其当前法理链解析，不靠名称匹配。
- 公爵级流官：本人县领、直接封臣的主领地必须在该公国的法理后代范围内。
- 伯爵级流官：只管该县及其合法附属领地，不借副头衔扩大范围。
- 帝国级流官：在本系统的中华霸权场景下没有法理领地封臣，不能直接持有低级领地，也不能统辖王国／公国／伯爵等领地封臣；已有领地封臣交回中华皇帝。宫廷成员、门客、家族身份等不等同于领地封臣，不因此误删。乱世割据帝国的实际法理与封臣结构不拿来为霸权内尚书官职授权。

帝国级尚书在霸权内无领地法理，是已明确的制度规则，应直接执行无领地／无领地封臣约束，不能以缺法理数据为由保留。对王国／公国／伯爵地域官职，若解析失败、数据缺失而无法判断其法理范围，则记录待核实，不把 UNKNOWN 当成“全部越界”而批量剥夺。

需要两项不同操作：

1. **本人越界持地**：转移该领地头衔及原生要求随附的男爵领，不连带没收其他合法领地。
2. **越界直接封臣**：改变封臣的实际领主，不把封臣自己的所有头衔转成皇帝个人财产。该封臣本人另有跨法理持地时，再以其自身主官职检查。

例：广东节度使拥有广西县领，把该县领交回中华皇帝或合法法理领主；广东节度使统辖广西伯爵，把该伯爵改隶皇帝或合法法理领主。二者不能混用“转头衔”效果。

例：江西公爵取得广东县领，不能因县领数量未超契约就保留；必须释出。广东法理公爵的身份取自该县当前法理公国的真实合法持有人，不能只找名字叫“广东”的角色。

## 4. 越界释出的默认目的地

按用户补充，默认交中华霸权皇帝；法理领主明确、同属目标体系且领主等级关系合法时，可以直接归还。若法理头衔未创建、无持有人、持有人属于外国、已在同一交接循环内，或等级不允许接纳该封臣，则交中华皇帝，不越境转让。

回收者是中华霸权权威头衔的当前合法持有人，不能从错误接任者的当前 top_liege 反推出“正确皇帝”。皇帝换人应跟随同一权威头衔；无合法收回者则暂停异常任务，不随机找皇帝。

法理领主临时接管县领、皇帝回收入库与正式继任分开记账；不能把“高级人物不得进入低级继承名单”解释为禁止一切临时接管，也不能让临时接管永久绕过最终持有规则。

如果临时接管者按其自身规则不能长期持有该县，必须继续走合法分封路径。例如帝国级尚书不能通过接管永久保有县领。通常交皇帝再由原版 AI 分封；AI 何时分封须实机观察，不保证下一天自动完成。需要精确保证重新分封时，应由协调器跟踪收回事项并经原生合法任命入口分配，不能把它当成已经完成的继承。

## 5. 法理长官代收公国与再次分封

用户确认：皇帝可能将河北大名镇公国直接授给河北转运使。转运使收到本省法理公国后，先核对允许保留的一个法理公国名额；该例不一定需要分封。允许本人保留一个本王国法理公国，优先王国首都所在公国。超出名额的法理公国才进入代收分封流程；所有外地公国仍按越界规则释出。这不是允许高级人物进入低级官职继承名单。

收到这类授予后，统一协调器先确定保留公国：已有合法的王国首都公国时保留它；同时持有多个合法法理公国时优先保留王国首都公国。首都公国不在本人名下时，不为凑名额强夺其他合法持有人的头衔；已有的一份合法非首都公国可保留。没有可确认的首都优先项而同时持有多份时，优先保留已有合法保留记录，再采用明确稳定的选择规则，不伪造历史或任意反复更换。

只对超出名额、需要转授的法理公国记录分封任务，并按以下顺序自动交出：

1. 验证收到者为适用范围内的王国级流官、公国确属其所保留王国的当前法理后代、授予来自本体系合法权威；越界公国走原有回收路径，不能就地分给自己的人。
2. 枚举有权受任的本国无地世族人物。这里“无地”是没有实际领地，不因其持有世族身份头衔而误排除；具体原生判定须核对当前Mod。
3. 对合格无地世族，使用该公国对应任命类型／法律的原生贤能评分与排序，选择最高者。不自创学习、武力或家族关系权重；文武官职各沿用自己的原生评分。
4. 只有没有合格无地世族时，才改从合法无地廷臣中按同一官职的贤能排序选人。优先使用该法理长官本国宫廷的合法任职人选；不扫描外国宫廷随意招人，不把已有实际领地的角色当成无地廷臣。
5. 通过原生授予公国流程任命被选者。授予公爵及以上头衔自动创建世族，沿用现有机制，不手动重复创建；验证新身份只生成一次。
6. 核验应转授的额外公国已离开转运使本人，接任者成为该王国下的合法公爵；转运使可保留的那一份法理公国不被顺带清走。新任者再接受唯一最高官职、低级持有、契约、法理及封臣检查。

同分沿用原生已有顺序；未提供可验证排序时记录明确的稳定决胜规则，不用随机反复抽取制造授任抖动。候选在执行前死亡、取得土地或资格改变时重选；不能把失效的“第一名”直接授任。

无合法世族或廷臣可授时，公国回交中华皇帝并记录未分配，不能永久留在转运使名下。不得为了制造候选强制生成角色。分封任务保存到真正转移完成，不因两天到期、重复授予回调或读档消失。

同一转运使同时收到多个本省公国时，先选定最多一份合法保留公国，其余逐份分封，每授出一份后刷新候选资格。第一份接任者已成为有地公爵，不能再次按“无地世族／廷臣”获得第二份；每份公国分别使用自身的任命类型和法理。

继承资格与行政代收须按真实事件来源分别判断：高级流官绝不能进入低级继承名单，但皇帝的合法行政授予可以短暂触发代收后分封。若原生回调在授予后才发生，就如实允许结算中的短暂兼任，不宣称没有任何中间帧。此专用任务必须先于普通“高级持低级直接回收”任务完成或合并，避免公国在转运使与皇帝之间来回弹跳。

## 6. 高级领主不得进入低级头衔继承名单

以候选人在本次撤任之前的真实最高领地等级作资格判断：高于目标等级者硬排除；同级候选允许调任；低等级／无地候选按原生任命资格处理。

不能先让帝国级尚书卸任、再因为他暂时只剩世族头衔而把他放进县令继承名单。原职等级和本次拟任最高官职须作为同一事务的资格依据，阻止通过暂时无地洗掉等级限制。

硬排除也包含国家归属、存活、官职／契约资格及循环状态。不能以减10000分冒充禁止；同级候选不能只因原来有官职而被全部排除，否则无法调任。

选择该目标头衔当前合法继承顺序中的下一人，第一人不合法则继续顺延。维护列表展示与实际授任一致，不能名单里仍有高官、接任后才默默纠正却宣称已经从名单排除。

本地原生 succession_appointment 文档没有证明可随意增加通用 valid_candidate 字段；具体硬资格入口、继承列表重算时机必须以当前上游实现核验。若引擎入口不能拦截，只能明确报告“授任后纠正”的限制，不能冒充完整满足需求。

## 7. 同级调任必须完整交出旧领地

用户合同：旧职及全部旧领地交接完毕、保留世族身份，然后才正式承接新同级官职。不是“留住新职后只释放几个旧同级官职”，也不是“旧县刚好在新地区内就偷偷保留”。

事务步骤：

1. 锁定目标新官职、原属国家、受任者原始等级与全部旧领地／直接封臣快照；预先计算合法接任与改隶去向。
2. 验证世族身份在失去领地后仍能保留、不会错误结束玩家游戏或切换身份；验证全部转移操作可合法执行。
3. 通过原生交易交接全部旧领地：旧主官职给其合法继任者；旧辖区县领与封臣按原辖区法理和契约归属交接，越界部分回收皇帝。不能把旧辖区全部土地硬塞给继任者而违反其新契约。
4. 核验受任者只剩受保护世族身份等非领地身份，未残留旧土地或旧领地封臣。
5. 正式授予新官职；新的合法县领、封臣只能来自新职的显式分配，不把旧财产改个标签冒充新辖区。
6. 复核最高官职唯一、低级持有、契约、法理、国家和封臣关系；对所有受影响接任者继续检查。

应优先选择可在同一原生结算事务中表达的安全交接，避免可见空档。不能为了满足表面顺序先不可逆撤完旧职，再发现新任命失败。原生事务能否提供所需的全套原子性／无地身份保护必须实机验证，不能仅凭模拟器承诺。

若上游只提供授任后回调，须先判定能否补入真正的前置入口；不能把“新职已到手后补清旧职”写成“继承前已经交出”。无法无损实现时需明确暴露限制，不暗改用户合同。

## 8. 连锁调任、循环和兜底

甲调任后空出的旧官职轮到乙，乙也必须完整交出自己的旧领地并保留世族身份，再承接该新职。乙的旧职轮到丙时同样执行。新系统显式安排下一接任者，不单靠 on_title_gain 自行再次触发。

链记录原属权威头衔、等级、访问人物、目标官职、原始等级、处理阶段与预期所有者。记录跨日与读档保留，不使用两天自动失效变量充当唯一记录。

发生甲→乙→丙→甲时，将闭环处正在等待分配的那份官职交中华皇帝，终止该分支；不连锁回滚已经合法完成的其他换任。没有合法继任者同样回收。皇帝回收是终态，不把皇帝当成下一位普通流官再清走。

重复回调幂等处理，不重放转移、不清除新事务记录。独立链、不同等级隔离；同一角色同一时间只能进行一份有领地写入的交接事务，跨等级影响也要重新核验。每步预算耗尽跨日继续，不将预算用完冒充循环。

## 9. 自动检查与旧状态修复

继承、授任、头衔丢失、主头衔、政府、领主、契约或法理变更后检查受影响集合；日常处理待检查队列，辅以目标中华体系内分批巡检，避免每日全世界遍历。

王国公国例外不改变同级调任的完整交旧规则：原王国、原保留公国和原县领仍全部交出；接任新王国后仅能按新王国的法理及保留名额配置领地，不能将旧公国带走。

最终检查顺序：适用范围 → 权威国家 → 王国合法保留公国选择及额外公国分封任务 → 最高官职及重复官职 → 禁持低级头衔 → 契约县领额度 → 本人越界持地 → 越界直接封臣 → 继任者继续检查。

启用／读档时分批审计已有混乱。没有可靠调任历史时，不能伪造“上一次调任前全部领地快照”；先按可确认的当前合法主官职修复最终持有及法理状态。跨国历史归属不明的项目应列为异常，不凭截图颜色反向改国。

审计、回收与重新分封分别记录原因和结果。不能把已改隶封臣再当成仍由旧领主直接持有的对象重复移交。

## 10. WoC 按钮布局（保留此前设计）

当前固定630宽、从左排按钮的容器和-360纵向偏移，会使仅两按钮显示时仍留出整排空位。改用真实右下地图区域宿主，按可见内容收缩并右对齐；两／三／五项切换时右边缘不漂移。保留全部原功能及窗口条件，不以隐藏按钮解决位置问题。

## 11. 必须先通过的场景

- 中华帝国级尚书：保留一个帝国级官职与世族身份，不保留任何低级领地或领地封臣；不得把省份法理挂入尚书名下。
- 中华王国级流官：最多保留一个本王国法理公国，优先王国首都公国；法理内县领依契约保留。皇帝将大名镇授给河北转运使时，先判断其是否为合法保留公国，仅在它属于应转授的额外公国时，优先贤能最高的合法无地世族，无合格世族则选合法无地廷臣；授任后自动创建世族、归属正确，不发生皇帝与转运使反复回传。
