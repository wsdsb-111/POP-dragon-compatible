# 1.3.21 日期栏、信条提示与圣物详情修复

本版按用户四张实机截图修复。七件圣物的专属插画正在由用户制作，本版只准备二维接入与临时原版图标，不代画或把三维预览当作最终插画。三维网格与材质完整保留，宫廷重铸继续可用。

## 原版世界报表

本机 CK3 1.20 `gui/hud.gui` 在右下百科按钮后定义 `ledger_window` 按钮，点击为 `ToggleGameView('ledger')`，原版快捷键 `ledger_window`，图标 `gfx/interface/icons/flat_icons/ledger.dds`。兼容包此前沿用功能扩展源 HUD，里面缺少这一控件，属于全文件合并遗漏；不能据截图认定为日期文本把现有按钮盖住。

本版原样补回该按钮。日期仲裁、速度按钮及其他旧HUD控件保持；测试先撤去新增按钮、复原既有日期差异后，要求与原扩展 HUD 输入哈希完全一致。未改东方/汉番源文件或用户播放集。

## 六派信条作用范围

本机 `_tenet_types.info` 对 `character_modifier` 明确规定：作用于所属礼仪将此信条作为核心信条的角色，而不是同父信仰的全部角色。六派各自的三条核心信条仍正确挂在六个 Rite 上。截图中的“所有龙之信条”来自原生 `CHARACTERS_OF_FAITH_MODIFIER[_SUBHEADER]`，它使用父 Faith 的信徒名；提示范围误导，不据此重写一套数值叠加系统。

本版按具体 TenetType 的18个ID，将两个标题映射为“仅铸火宗信徒”等对应分支。映射不依赖当前玩家礼仪，以免查看另一派时显示错派。非自定义信条、无信条上下文等情况回退原版标题。本地化使用有原生用例的 `ObjectsEqual`、`GetTenetType` 和嵌套 `Or`。

三份教义/信条/Rite定义与已安装1.3.20整包逐字哈希相同，全部数值、美德罪恶和礼仪挂载保持。只修说明，不重复发放修正。

## 圣物二维与三维分离

原版库存和物品提示画的是 `Artifact.GetIcon` 二维图，并以240×240切帧。上一版使用512×512三维离线渲染图，不符合这一切帧规格，不能当作完成的专属装备插画。

个人版本暂用对应的原版二维图标：冠、礼器、书、戒指、圣物盒、盔甲、长矛。用户的新插画到齐后再替换；届时会检查透明通道、主体边距和240像素帧布局。当前映射见 `artwork/dragon-relics/v1321-presentation.json`。

库存 visual 的 `asset` 与 `portrait_asset` 使用合法的原版装备实体，自制 `mm_relic_*_entity` 只绑定 `*_court_visual`。这是保留原生 visual schema 和角色肖像回退；库存格本身仍只画二维图。原生重铸蓝图负责 inventory→court 类型/visual 切换，已带底座的自制模型不额外挂第二个原版支架。现有七件网格、材质及离线源图未改字节。

## 宝物要求与滚动

此前详情窗直接调用 `Artifact.GetModifierEffects`，库存 tooltip 则调用 `ARTIFACT_EFFECT`。后者会显示原生“如果你满足要求”，其中“要求”通过 `ARTIFACT_EFFECT_REQUIREMENT_TT` 悬浮展示真实 `Artifact.GetCanBenefitPlayerDesc`，即截图4的交互。

本版详情窗也使用该原生入口。效果、持有者/圣地信息、非空 fallback 与简介放进同一原生 scrollbox，避免固定效果列表把说明挤到窗外；空 fallback 不显示空标题。右侧历史、宣称者、重命名、重铸等操作保持。

同时为本轮新增圣物决议补齐原生确认按钮文本；对全局求爱/勾引预计算增加 Faith/Rite 存在性守卫，避免世界生成时提前查询尚未创建的自定义信仰。此修正不改变持有圣物后的收益数值。
