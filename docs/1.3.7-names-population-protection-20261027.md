# 1.3.7 家族命名与人口清理豁免（2026-10-27）

## 新家族名称

截图中的`ERROR:[location.GetBaronyNameExplicitlyNoTooltip]`对应原生动态家族命名模板。新角色创建宗族时会触发`on_dynasty_created`；某些文化选择地点模板，而该创建时序未必具备模板所需的地点上下文。

开局25家混血家族创建前设置原版`block_dynamic_dynasty_naming`一天变量，再创建宗族并用`house = { set_house_name_from_dynasty = dynasty }`复制稳定宗族姓氏。原版日本决议使用相同阻断方式。低出身龙蛋子代需要自创宗族时也采取同样处理；已有家族归属的后代仍继承原家族。文化、父母、分级、数量与黄金瞳不改。

这防止安装后新建家族产生同类名称。旧档现有名字没有自动重置：创始人标记不能可靠证明当前名字仍为错误模板，也不能排除玩家手动改名；未发现可可靠比较这段错误显示字符串的脚本条件。已经出现错误的家族可在原生家族面板手动改名。本补丁不自动覆盖正常或手改名称。

## 保护规则

新增最后加载的`character-preservation`模块。完整包为12模块/12个依赖，新增依赖“Born of This Land 1.19”（3740401066）。该模块需要现有王座/混血及基础兼容模块，确保显式引用的特质已定义；按模块组包时须选择该模块才包含本轮清理保护。

统一条件`mm_cleanup_is_protected`同时检查引擎`is_immortal`、角色`has_trait_with_flag = is_immortal`及明确的龙血特质，兼容只设永生属性、只设旗标以及两者都有的上游实现。对应不朽/不老不死、野生/驯服/传奇龙体、四王及合一体、黑白皇、蛰眠、传奇来源、沐浴龙血、初代/S/A/B/C/黑血、龙血双相之躯均受保护。不依赖单纯加健康或预期寿命来抵挡脚本死亡。

## 数量与审计范围

停止杀掉已有龙后，降低上限不会使存量立即降到上限。原自然随机生成仍用全体存活龙数和巢穴上限提前判断；野蛋孵化沿用另一套计数，排除王族/初始龙后判断10/30/50等容量，因此两者不是同一个总数上限。手动孵蛋等原显式创建仍可超额，不宣称所有出生入口均受统一上限控制。

读取当前51项播放集，包含50个Workshop Mod和本地兼容补丁，对启用Mod及原版`common/events`进行静态审计。除上表外，VIET临终梦境的入口已有`is_immortal=no`且属于剧情死亡；Intelligent AI及汉番部分死亡只处理刚创建的临时剧情/家谱人物，本轮未改。不会因`death_old_age`或`death_vanished`名称本身就改写所有剧情。

审计记录为`.build/v137-age-audit.json`。静态关键词和定义排查不能证明未公开引擎内部或所有间接路径绝无清理，其他未启用Mod也不在已验证范围；后续更换Mod或上游更新应重新核查。
