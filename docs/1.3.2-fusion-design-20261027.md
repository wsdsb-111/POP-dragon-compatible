# 1.3.2 王座龙血、侵蚀与融合设计（2026-10-27）

状态：前置模型审查已由 root 完成，用户方案已说明，已获授权进入实施；代码正在独立 ascension 模块落地。本代理没有运行 Node、启动 CK3 或安装，专项测试仍待 root 串行执行。本文只属于独立 `compat-v111` Mod 工程，不改父目录 VOTC 应用，也不改原 MYV／游戏文件。

## 0. 用户后续强约束与最终实施选择

本节优先于下方早期提案：**侵蚀胜出与融合胜出都获得可逆化龙，只有完结后才能切形**。融合胜出保留本人姓名／身份，获得旧完成态全部buff和准确源龙形态，默认人形；侵蚀胜出继承真实血源姓名与王权，默认龙形，仍能化人。同一人物 ID、父母、文化、家族、头衔与已有祖源不因切形而改变；形态切换只改显示 flags，不重算属性或结局。无可靠来源的旧完成态保留全部旧 buff，不自动猜造新形态。

实际模块使用 `mm_asc_dragon_body`，龙形 `mm_asc_dragon_form`、人形 `mm_wyvern_human_form` 互斥同步；`mm_asc_visual_family` 为1火／2地／3海／4天／5白／6黑，0只允许实际来源原色回退，不冒称某帝。`mm_asc_source_size/color` 精确快照来源原字段。模型代理独占 gfx／genes 外观模板并提供桥接，不由 ascension 复制或重定义整套 gene。

所有新增游戏逻辑都在 `patches/wyvern-ascension` 中以显式晚加载覆盖接入；capture／kings 原文件保留，旧版本源码合同继续有据。旧完成态 trait 在本模块原样保留全部 gameplay 字段，仅增加显式显示名、来源desc和与僭主态互斥。血奖励原API保留为单行转接。王座锚的 `current_incarnation` 是真值，十个 `mm_asc_seat_<ID>` global scopes 只在初始化／接位时从锚派生，供原生唤醒决议查询。

新王本人另有“吞噬我的双生子”入口，解决原“人类命令两个羁绊宠龙”入口不能给新玩家龙王使用的问题；旧入口与新入口共用 `mm_asc_unite_twins_effect`，相同当前席位／双生互指／已醒／一次合一门禁。真死者仍不复活。源龙吸收只调用 lineage 的 `mm_dragon_append_absorbed_origin_effect = { TARGET = scope:mm_asc_claimant }`，从不把猎杀伪装成生物祖源。

## 1. 已查明的现状与实现边界

已完整阅读桌面《CK3 龙族系统后续施工任务书.txt》。模型、固定龙王、混血祖源和沐血入口都在当前兼容 Mod 的独立 wyvern 模块中；原 MYV 提供基础物种、模型及生命周期，六位核心角色与四系双生王权是本工程新增系统，不应回写原 MYV。

- `patches/wyvern-capture/mod/common/traits/mm_wyvern_dragon_blood.txt:2`：旧 `mm_wyvern_bathed_in_dragon_blood` 包含永生、不因年龄丢勇武、health／elderly_health／life_expectancy 各 +666、fertility +1、years_of_fertility +666、long_reign_bonus_mult +1、prowess +10、monthly_prestige +2，以及 immortal 相关 flags。
- `patches/wyvern-capture/mod/common/scripted_effects/mm_wyvern_trophies.txt:76`：唯一龙血奖励后端只在击杀目标真死亡、击杀者存活、目标传奇身份成立后直接加旧特质。没有记录龙血来源，也没有侵蚀、融合或王权继承。调用者包括 victory 后端和徒步／骑乘击杀分支，不改掉任何真实死亡前置条件。
- `patches/wyvern-kings/mod/common/scripted_effects/mm_royal_identity_effects.txt`：固定十个历史 ID 一次 bootstrap、王座号、双生引用、创造者关系和每日恢复队列。重复调用只给仍存活的固定王权补每日队列，不会复活真死者。
- `patches/wyvern-kings/mod/common/character_interactions/mm_royal_devour.txt`：有同 ID 幸存者吞噬双生、升级 complete、记实际死者引用及四系一次性 united 标记；它不是人类继承死者王权。
- `patches/wyvern-kings/mod/common/decisions/mm_royal_awakening.txt`：唤醒目标与羁绊条件大多写死历史 ID；双生吞噬要求 fixed_identity。这些状态不能只给新角色一个王权 trait 就算接通。
- `patches/wyvern-bloodline/mod/common/scripted_effects/mm_dragon_lineage.txt`：已有真实源龙引用列表、去重及 16 项可见投影；不应用新龙血变量覆盖旧 `mm_dragon_origins`、代数或亲缘。

结论：现有王权基础可复用，但没有完整的死者王权继承。必须补身份接续、原生姓名复制、可操作龙身、固定引用解析和旧档兼容，不能只加事件文案。

## 2. 推荐的模块与最小接入

新增 `patches/wyvern-ascension/mod`，依赖 `wyvern-kings`。独立存放 trait、script values、effects、triggers、decisions、on_actions、events、modifiers、localization 和必要 portrait 桥；源文件清单登记在该模块 `sources.json`。由 root 统一更新 modules／版本／组包与测试清单。

生产共享点仅以下几类，先由 root 分配所有权，避免与 lineage 代理同时编辑：

| 共享点 | 需要的改动 | 建议所有者 |
|---|---|---|
| 龙血奖励后端 | 原 key 保持，主体改为调用新获取 effect；保留真死亡／传奇／存活门禁 | ascension，经 root 授权 |
| `mm_royal_*` 当前身份及双生解析 | 历史 ID 解析到当前 incarnation，仍允许死者作为历史来源 | ascension |
| 唤醒、吞噬与 daily bootstrap | 使用当前身份；不复活真死者；把新继承者纳入每日恢复 | ascension |
| `myv_is_wyvern`、wild eligibility | 纳入新龙身；排除可操作的龙族君主成为野兽猎杀／捕获对象 | ascension |
| 源龙多源增量接口 | 将新猎杀来源追加／去重；不重置已有列表或分支来源 | lineage 提供，ascension 调用 |

原 trait tooltip 不必改；新特质的两个命名 track 可由它直接枚举。若实现选择覆盖已有 effect／trigger，须登记覆盖合同，避免依赖未知的加载顺序或在两个模块留下竞争定义。

## 3. 旧档与两阶段特质

保留旧 `mm_wyvern_bathed_in_dragon_blood` key 和原全部 gameplay 字段，显示名改为“王座执掌之血”。已有持有者一律按已完成态处理，不突然降级、撤销永生、补侵蚀或补付费仪式。旧存档没有可靠击杀来源时明确显示“来源未载入／旧档未记录”，不按当前持有的材料、同名人物或最接近的龙王推造来源。

新获得使用 `mm_asc_usurper_blood`，显示“王座僭主之血”，与旧完成态双向 opposites，获取与每次结算仍显式互斥检查。推荐初始正面值仅 prowess +2、health +0.5、monthly_prestige +0.25；不提前给永生、+666 生育／寿命或长统治翻倍。完成融合才恢复旧 trait 的全部值，不手抄一份逐渐漂移的完成态。

每人只运行一场双轨竞赛。已在僭主阶段、已融合或已龙化时，后续击杀仍走合法战利品与吸血升级，但不覆盖本次竞赛的来源，不重置进度、不重发沐血奖励。猎杀来源的额外祖源可经 lineage 的非破坏追加接口保留。

新获取准确保存刚被杀死目标引用 `mm_asc_blood_source`。它是本次龙血仪式的直接来源，不等同于生物祖先；原生父母、真实父亲、原多源祖源与来源等级全部保留。新特质及完成态 tooltip 以此真实引用显示来源姓名。

## 4. 双轨道与唯一结算

原生 `tracks = { mm_asc_erosion = {...} mm_asc_fusion = {...} }`，两条上限均 100。经验只存在 trait track，不另维护容易漂移的 0–100 变量。数值集中于本模块 script values：侵蚀每年 +10，付费仪式每次 +20，五次仪式融合；未仪式时十次年度推进龙化。获取当年从 0 开始，年度回调以当前新年统一结算，界面明确是年度推进，不伪称按获得周年。

`yearly_global_pulse` 只遍历模块自己的 `mm_asc_candidates`，每人记录 `mm_asc_last_erosion_year`，同一年重复 pulse／读档回调零追加。仪式同样记录 `mm_asc_last_ritual_year`，比较原生 `current_year`；日历年内最多一次，12 月与次年 1 月各一次属于两个年度，说明中写清。`current_year` 作为保存值在本机 vanilla `events/war_events/combat_events.txt:2293` 等有实际用例。

每个入口都调用同一个 resolver，顺序为：

1. 先验证角色存活、持有 usurper、没有任一终结状态。
2. 在任何改值前处理已经到顶的旧／异常状态；若两条已同时 100，固定按侵蚀优先收口并记诊断，绝不连跑两结局。正常入口每次只推进一条，不会制造同刻双满。
3. 支付仪式：再次复核成年、自由、可行动、资源、年度锁与侵蚀尚未满；先记年度锁并扣款，再加 fusion XP，再立即 resolver。
4. 年度推进：先记年度锁，再加 erosion XP，再立即 resolver；若已终结，不触发后续低语。
5. resolver 在同一 effect 内先写不可逆 `mm_asc_outcome`（fusion／dragon），再做唯一分支，移除 usurper 和本模块候选资格。任何后续 callback 先检查 outcome，零重放。

同日的年度 pulse 与玩家决议按引擎实际串行先后处理，先达到上限并写入 outcome 的入口胜出；另一入口不得收费或再推进。若侵蚀已满，不能靠尚未结算的仪式覆盖结果。

## 5. 侵蚀、低语和有界仪式

侵蚀必须实际影响属性。推荐以 track 阶段绑定本模块专用的非遗传健康／社交修正，阈值采用 0／25／50／75，分别为：

| 侵蚀阶段 | 外交 | 健康 | 一般好感 |
|---|---:|---:|---:|
| 0–24 | -1 | -0.25 | -5 |
| 25–49 | -2 | -0.5 | -10 |
| 50–74 | -3 | -0.75 | -15 |
| 75–99 | -4 | -1 | -20 |

实施时只让一个本模块阶段 modifier 生效；不要误以为 track 各门槛自动累计／自动互斥，必须用执行测试验证实际选级值。负面抵消初始正面后仍是明显弱化状态。

“王座低语”从取得龙血即有效，用专用 modifier 增加压力收益并降低压力恢复。每次年度推进后最多掷一次，按侵蚀阶段提高触发概率／压力量，绝不月月循环刷事件。事件至少有“强行压制”（实加压力）和“向残响让步”（专用偏执／疯狂发作 modifier 加压力）等有代价反馈；来源存在时文案显示真实来源名。

推荐优先使用 `mm_asc_whisper_paranoia`／`mm_asc_whisper_madness` 专用有期限 modifier 表达偏执与疯狂，而非替换原有 personality 或直接乱加永久 `paranoid`／`lunatic_1`。这样融合可精确撤本系统添加项，不误治原病。若确需授予 vanilla 疯狂 trait，必须在新增前记录“之前没有此 trait 且确由本模块新增”，并为其他系统后来独立授病定义保留策略；无法分辨来源时不自动移除。推荐本版避免这项复杂度。

仪式使用原生决议，不引入尚未验证的圣地旅行系统。建议每次 250 金币、250 虔诚、100 威望，资源数值集中配置。只有有效执行才扣款与锁年；失败、拒绝、预览、失能／监禁或结算已终结均零消费。AI 如参与也必须走相同支付与年度门禁，不能免费后台融合。

成功融合后：移除 usurper、全部 `mm_asc_erosion_*` 与 `mm_asc_whisper_*` 项，添加旧完成态；保留准确血源；不清历史上已产生的 stress，不删除原有心理／健康 trait，不治疗第三方 modifier。队列／pulse 后续直接跳过。完成态和龙化态不能并存。

## 6. 名字继承已有原生可行路径

本机原生游戏已使用：

```text
change_first_name = { template_character = scope:namesake }
```

证据：`game/events/birth_events.txt:3565`，同文件 `3977` 附近选择 relatives 时明确提高 `is_alive = no` 人物的权重，并将其保存为 namesake；`game/events/yearly_events/bp1_yearly_james.txt:1627` 也以 root 作为模板。因此可在结局中对当前人物执行 `change_first_name = { template_character = var:mm_asc_blood_source }`，复制实际被杀对象的名字，保留继承者原人物 ID／性别／家族。

这复制的是 first name，不伪造死者 house、王朝或生物父母。王权昵称另按对应王权类型配置。来源已合一并实际名为苏尔特尔等时复制其当前名字，而不是回退某个固定初始名。来源缺失时不伪造名字、不跳过缺源检查后宣布完成。脚本证据证明接口可用；实际名字本地化显示、改过名的来源和跨语言存读档仍须 CK3 实机验收。

## 7. 同 ID 真龙化与玩家可操作性

不能直接把人类塞进原野兽初始化链。已查明三个实际风险：

1. 原 `myv_wyvern`／tamed／legendary 物种 trait 含 `inheritance_blocker = all`、`claim_inheritance_blocker = all`、禁婚／子女／领军等；不适合直接当作可操作君主身体。
2. 原 `myv_wyvern_nonhuman_maintenance_effect` 会开除宫廷职位／移出宫廷；`myv_wyvern_human_death_protection_effect` 清压力、释放监狱并删除教育／生活方式／性格／健康 trait；`myv_apply_wyvern_identity_effect` 强改为 MYV 技术文化和 pagan。
3. 原 `myv_wyvern_game_rule_effects.txt:45–56` 对 `myv_living_wyverns` 超额按年龄执行 `death_old_age`，连王权永生也不能挡这个直接 death。

只读搜索未发现 MYV 用 `set_ai`、玩家切换或明确剥夺领地的命令；但这不能证明原物种可以直接给玩家。推荐最小可操作方案：

- 新 `mm_asc_dragon_body` 身体 trait，两种完结状态均获得可逆化龙；侵蚀胜出拥有对应真龙王权身份但不带野兽禁继承／禁婚／禁领军／强制零生育字段；由 `mm_royal_*` trait 提供王权永生和对应能力。扩展 `myv_is_wyvern` 识别它，保留实际 dragon gameplay 分类。
- 新龙身有专用 trait portrait modifier，用原 MYV 已存在的 `gene_myv_wyvern` body 附件与 `gene_myv_no_portrait = no_portrait` 隐藏人体；专用高优先级 portrait 组引用已验证成熟体型／颜色模板，并抑制人类衣饰。正常龙、模型、骨骼与贴图字节均不动。只需本模块龙身的成熟外观，不复制整套 hatchling 到 tier_10 成长表。
- 结局时同 ID 添加新龙身和来源对应的王权 trait，显式保存旧文化／信仰、头衔、家族、性别、母父／real_father 和旧 origins 快照用于测试；生产不改这些数据，也不调用 `create_character`／`set_mother`／`set_father`／`set_house`／`set_culture`。
- 将两个结局的可逆龙身持有者加入 `mm_asc_sovereigns`，不加入原 `myv_living_wyverns`。王权每日恢复通过现有 queue effect 直接接通，加载时从独立索引补队列。设置尺寸／颜色／饥饿等 canonical 战力必需变量后调用画像 flags 刷新与原唯一 prowess 刷新；不调用野兽 identity initializer，不自动野游、兽栏圈养或消耗兽栏费用。
- wild eligibility 显式排除 `mm_asc_dragon_body`；对可被直接调用的野兽身份／非人维护后端加此身体的 guard，作为误调用防线。原野兽行为保持，不能给全体龙移除维护。
- 新君主可按原身份保留玩家操作与政治关系；不把自己变成自己／别人的坐骑或羁绊宠物。原人工繁育已由用户放宽，本模块不重做其同意／羁绊与成年规则。

该方案比直接给 `myv_wyvern_legendary` 多一个 body trait 与 portrait 桥，但避免原生规则改坏君主，且不需要改全套龙生命周期。实际地图／宫廷／玩家头像、领军、继承、保存加载和没有 game over 必须实机验证，不能用有限执行器的“trait存在”冒充完成。

## 8. 王权接续、双生与固定 ID

推荐以原固定人物作为不可变“席位锚”，在其上保存 `mm_asc_current_incarnation` 指向现任人物。新增者保存 `mm_asc_seat_anchor` 和 `mm_asc_predecessor`。四系双生是八席，加黑白皇两席，不能把每系只有一个 throne 数字误当作十人的唯一身份。

- 初始化每席只在变量缺失时指向原固定人物；原人物死了也不重造、不改 alive、不把 holder 重置回死者。
- 获取时记录实际被杀 source，其 anchor 沿继承链携带。只有结局时来源仍是该 anchor 的当前 dead incarnation，才把 holder 原子更新为当前角色；冲突／来源不可用须在结局前拦住并留下诊断，不在不可逆写入之后补猜。
- 对四系未合一的来源：继承 `mm_royal_dragon_king`、原 throne／creation_throne，与对应另一席当前活着的人物重接 reciprocal twin variable／active relation。旧死者引用仍在 predecessor／血源；活跃双生关系不留下三人互指。若另一席也已死亡待接续，先保留对其 anchor 的引用，待其 incarnation 接续时再双向连接。
- 已 complete 来源继承 complete，携带 consumed_twin 历史引用并保留原 united 标记，绝不恢复死掉的被吞噬双生；完整王权不会重复合一。白／黑皇来源分别继承对应真实 rank，不能两者都降成普通双生王。
- 吞噬资格从“必须原 fixed_identity”调整为“有合法席位锚／当前 holder、当前双生互指、同座、双方活着已醒、一次 united 未用”，避免给新角色冒加 fixed_identity 来欺骗历史初始化。
